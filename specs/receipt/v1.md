# NEMESIS Mission Receipt v1

## Encoding

A receipt is a canonical CBOR COSE_Sign1 array:

1. protected header byte string containing canonical `{1: -8}` (`alg = EdDSA`);
2. empty unprotected map;
3. canonical CBOR payload byte string;
4. 64-byte Ed25519 signature.

The signature input is canonical CBOR `['Signature1', protected, h'', payload]`. The standalone verifier rejects indefinite arrays/maps, wrong lengths, unknown protected bytes, trailing bytes, malformed digests/identifiers, signature failure, non-`COMPLETE` state, and any mandatory claim not marked `VERIFIED`.

The payload is a fixed eight-element array:

1. schema text `nemesis.receipt/v1`;
2. 26-byte mission identifier;
3. authoritative event sequence;
4. terminal state text;
5. 32-byte final source digest;
6. 32-byte ledger-chain head;
7. claim array;
8. residual text array.

Each claim is `[id, mandatory, epistemic-status, evidence-digest]`. Status codes are `0 = VERIFIED`, `1 = BELIEVED`, and `2 = UNKNOWN`. Status does not inherit authority from the signer; Core and Kernel must accept evidence before constructing a completion payload.

## Local signing identity

The Ed25519 seed is stored as a generic password in the macOS login Keychain under service `dev.nemesis.receipt.seed.v1` and account `local-default`. Creation delegates secret entry to the stable Apple-signed `/usr/bin/security` process over stdin and grants Keychain access only to `/usr/bin/security`. The seed is absent from argv, worker environments, receipt output, and signer JSON output. Subsequent reads also use the stable binary, avoiding the access prompt that unsigned, frequently rebuilt local signer binaries trigger when they own the item ACL directly.

The signer writes receipt and public key through same-directory temporary files, `fsync`, atomic rename, and parent-directory sync. It reports `private_key_exported: false`; the private seed is zeroed from intermediate buffers after key construction.

## Independent verification

```sh
runtime/target/debug/nemesis-verify \
  --receipt receipts/phase-6/receipt.cose \
  --public-key receipts/phase-6/receipt.pub
```

Exit zero and JSON `"verdict":"VERIFIED"` apply only to the bounded encoded predicates. Any one-byte mutation in the repository test corpus exits nonzero with `"verdict":"REJECTED"`. The verifier starts no daemon and calls no model.

A valid signature does not establish universal truth, whole-product correctness, legal clearance, public-release readiness, or correctness of external cryptographic/operating-system libraries.
